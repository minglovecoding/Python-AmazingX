## 📚Chapter 1: Data Representation

###  📝 Lecture 01 · Number Systems（数制）

### 📌学习目标

1. 解释为什么计算机使用 binary（二进制）表示数据。
2. 在 denary（十进制）、binary 和 hexadecimal（十六进制）之间转换。
3. 说出 hex 常见用途，并解释它为何便于人阅读。

### 1. 为什么用 binary？

电子电路可以区分两种稳定状态，常用 `0` 和 `1` 表示。**bit**（binary digit）是一个二进制位。注意：数字 `101` 在不同进制中代表不同的量，因此写答案时最好标注下标，如 `101₂` 和 `101₁₀`。

| 系统 | 英文 | 基数 | 可用数字 |
|---|---|---:|---|
| 二进制 | binary | 2 | 0、1 |
| 十进制 | denary | 10 | 0–9 |
| 十六进制 | hexadecimal / hex | 16 | 0–9、A–F（A=10，…，F=15） |

> **提问：** `10₂` 为什么不等于 `10₁₀`？答：前者是 (1×2+0=2)，后者是十。

### 2. Binary ↔ Denary

每位的权重是 2 的幂；从右往左依次为 1、2、4、8……

| 位权 | 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `10110110₂` | 1 | 0 | 1 | 1 | 0 | 1 | 1 | 0 |

因此 `10110110₂ = 128+32+16+4+2 = 182₁₀`。

反向转换：将十进制数拆成 2 的幂。例如 `156 = 128+16+8+4`，所以 `156₁₀ = 10011100₂`。也可以不断除以 2，**从下往上读余数**。如果题目要求 8-bit，左侧补零到 8 位；例如 `5₁₀ = 00000101₂`。

> **检查点：** 8-bit *无符号*数的范围是 0–255。超出范围时不能只补零。

### 3. Binary ↔ Hexadecimal

因为 `16 = 2⁴`，**1 个 hex digit 恰好对应 4 bits**。

| Hex  | Binary | Hex  | Binary |
| ---- | ------ | ---- | ------ |
| 0    | `0000` | 8    | `1000` |
| 1    | `0001` | 9    | `1001` |
| 2    | `0010` | A    | `1010` |
| 3    | `0011` | B    | `1011` |
| 4    | `0100` | C    | `1100` |
| 5    | `0101` | D    | `1101` |
| 6    | `0110` | E    | `1110` |
| 7    | `0111` | F    | `1111` |

从**右向左**每四位分组：`110101101011₂ = 1101 0110 1011₂ = D6B₁₆`。左端不足四位时补前导零：`101101₂ = 0010 1101₂ = 2D₁₆`。反向转换逐位替换：`A7₁₆ = 1010 0111₂`。

### 4. Hex ↔ Denary

hex 的位权从右向左是 `1、16、256、4096…`：

`2D₁₆ = 2×16 + 13 = 45₁₀`。

十进制转 hex 可连续除以 16：`430 ÷ 16 = 26 余 14(E)`；`26 ÷ 16 = 1 余 10(A)`；`1 ÷ 16 = 0 余 1`。倒读得 `1AE₁₆`，回算 `256+160+14=430`。

### 5. 为什么使用 hex？

长串二进制对人而言难读、难抄；hex 更短，但**并不改变计算机实际保存数据的方式**。教材举到的场景包括 error codes、MAC addresses、IPv6 addresses、HTML colours。例如 HTML `#3A7F20` 以三组十六进制分别表示 R、G、B；每组从 `00` 到 `FF`。

### 课堂练习

1. 把 `11001010₂` 转成 denary。写出相加的位权。
2. 把 `73₁₀` 写成 8-bit binary。
3. 把 `101111001₂` 转成 hex。
4. 把 `9C₁₆` 转成 denary 和 8-bit binary。
5. 用两句话解释为什么错误代码和颜色代码经常使用 hex。（2 marks）

### Answers:


1. `128+64+8+2 = 202₁₀`。
2. `64+8+1`，所以 `01001001₂`。
3. `0001 0111 1001₂ = 179₁₆`。
4. `9×16+12 = 156₁₀`；`1001 1100₂`。
5. 一位 hex 对应四位 binary，因此可以用更短的字符串表示同一数值；人更容易阅读、记录和检查。不要写“hex 更省储存空间”，因为这里只是人看的表示法。

### 📝 Lecture 02 · Binary Arithmetic, Shifts & Two’s Complement

### 📌 学习目标

1. 完成 8-bit 二进制加法并识别 overflow。
2. 执行固定长度寄存器中的 logical shift（逻辑移位）。
3. 解释 8-bit two’s complement（补码）的范围，计算和读出负数。

### 1. Binary addition（二进制加法）

| 计算 | 本列写 | 向左进位 |
|---|---:|---:|
| `0+0` | 0 | 0 |
| `0+1` 或 `1+0` | 1 | 0 |
| `1+1` | 0 | 1 |
| `1+1+1` | 1 | 1 |

从**最右侧**开始算，和十进制加法一样逐列进位。例如：

```text
    00101101  (45)
  + 00010111  (23)
  ----------
    01000100  (68)
```

**无符号 8-bit overflow：** `11110000₂ (240) + 00110000₂ (48) = 1 00100000₂ (288)`；结果需要 9 位，8-bit 放不下。不能把截断后的 `00100000₂` 当作完整的 288。

### 2. Logical shift（逻辑移位）

移位前先固定宽度，例如 8-bit。移出的位丢弃，空出的位补 `0`。

```text
原始    00010110  (22)
左移 2  01011000  (88)
右移 1  00001011  (11)
```

若**没有 1 被左侧移出**，左移 (n) 位相当于乘 (2^n)；右移 (n) 位相当于对**非负整数**做整数除以 (2^n)，余数被丢弃。例：`00000111₂ (7) >> 1 = 00000011₂ (3)`，不是 3.5。

若重要的位被移出，就不能再直接用乘除来判断实际保存的结果：`11000000 << 1`（8-bit）得到 `10000000`，原来的最高位已经丢失。

> **易错提醒：** logical right shift 左侧补 0；不要套用其他课程中的 arithmetic right shift（符号位扩展）。

### 3. Two’s complement（补码）

同样 8 个 bit，解释方式变了：最高位的位权是 `−128`，其余仍是 `64、32、16、8、4、2、1`。

| 最高位 | 范围（8-bit） | 示例 |
|---|---|---|
| 0 | 0 到 +127 | `01111111₂ = +127` |
| 1 | −128 到 −1 | `11111111₂ = −1` |

读负数：`11010110₂ = −128+64+16+4+2 = −42`。求 `−42`：先写 `+42 = 00101010`，逐位取反 `11010101`，再加 1，得到 `11010110`。**取反加一只在事先固定 8 位的前提下进行。**

```text
 +42   00101010
 取反  11010101
 加一  11010110  (−42)
```

`10000000₂ = −128`，`01111111₂ = +127`。`10000000` 作为**无符号数**则是 128；读题先确认采用哪种表示法。对于有符号加法，overflow 的判断须按有符号范围；例如 `01111111 (+127) + 00000001 (+1)` 得 `10000000`，超出 +127，发生有符号 overflow。

### 课堂练习

1. 把 `00110110` 与 `00011011` 相加；把结果转成 denary。
2. 在 8-bit 寄存器中，把 `00101101` 左移 1 位、右移 2 位，分别写出结果。
3. 写出 `−19` 的 8-bit two’s complement。
4. 把 `11101011` 按 8-bit two’s complement 读成 denary。
5. 比较 `11111100 + 00000101` 在 8-bit 无符号加法中的结果，并指出是否发生 overflow。（2 marks）

### Answers:


1. `01010001₂ = 81₁₀`。
2. 左移 `01011010`（90）；右移 `00001011`（11；低位丢弃，不能当作精确的 45÷4）。
3. `+19 = 00010011` → 取反 `11101100` → 加 1 `11101101`。
4. `−128+64+32+8+2+1 = −21`；或取反加一得 21，再加负号。
5. 数学上的和是 `252+5=257`，需要第 9 位；在固定 8-bit 中只留下 `00000001`，发生 unsigned overflow。

### 📝 Lecture 03 · Representing Text, Sound & Images

### 📌 学习目标

1. 说明 character set（字符集）如何将字符映射到二进制编码。
2. 解释 sampling rate 和 sampling resolution 对数字音频的影响。
3. 解释 pixel、image resolution、colour depth 对位图质量与数据量的影响。

### 1. Text：字符如何存储？

计算机存储的是数值编码。**character set** 规定字符与编号的对应关系：先将字符映射到编号，再将编号写成二进制。比如在 ASCII 中，`A` 对应十进制 65，即 `01000001₂`；这只是示例，不是所有语言的字符都能用 ASCII 表示。

| 名称 | 用途与区别 |
|---|---|
| ASCII | 较早的字符集，适合基本英文字母、数字、标点和控制字符。基本 ASCII 有 128 个编码。 |
| Extended ASCII | 可扩充更多字符；不同扩展方案的映射未必相同。 |
| Unicode | 为多种语言和符号分配字符编号；能表示远多于 ASCII 的字符。 |

**教学提醒：** Unicode 是字符编号体系，UTF-8 等是具体的编码方式。不要笼统声称“每个 Unicode 字符固定占 2 bytes”。

### 2. Sound：声音如何变成数据？

声音是连续变化的波形。**sampling（采样）**在规定的时间间隔测量波形的 amplitude（振幅），并把每个测量值编码成二进制。

| 术语 | 含义 | 增大之后 |
|---|---|---|
| Sampling rate（采样率） | 每秒采样次数；单位 Hz | 单位时间内采样点更多，通常更接近原波形，文件更大 |
| Sampling resolution / bit depth（采样分辨率） | 每个样本的 bit 数 | 可区分更多振幅等级，量化更细，文件更大 |

例如 8-bit 样本有 `2⁸ = 256` 个可能的量化值；16-bit 样本有 `2¹⁶ = 65,536` 个。**更高的值通常提高保真度，但质量还受录音设备和信号本身影响**。

> **课堂提问：** 采样率由 8 kHz 变为 16 kHz、录制时间和其他条件不变，未压缩的样本数量怎样变化？答：变成两倍。

### 3. Images：位图如何存储？

**bitmap image** 由一格格 **pixels（像素）**构成；每个像素的颜色以二进制表示。

- **Image resolution（图像分辨率）**：宽 × 高，例如 `800 × 600 = 480,000 pixels`。更高通常保留更多空间细节，也需要更多数据。
- **Colour depth（色深）**：每像素用于表示颜色的 bit 数；`n bits` 可表示最多 `2ⁿ` 种不同编码。1 bit → 2 色；8 bits → 256 色；24 bits → 16,777,216 色。
- 更大色深增加颜色选择；更高分辨率增加像素数。**两者是不同的维度**，都会增加未压缩文件大小。

**例：** 从 `400×300` 改为 `800×600`，宽高各翻倍，总像素数变成 4 倍；若色深不变，像素数据也约为 4 倍。文件头等额外开销未计入。

### 考试作答框架

问“为何文件变大”时写出因果链：**某参数增加 → 每秒样本 / 总像素 / 每像素 bit 数增加 → 需要存储更多 bits**。仅写“质量更好”不够具体。

### Questions:

1. 解释为什么 ASCII 不适合直接表示世界上所有语言的文字；指出可用的字符体系。
2. 一个录音每秒取 20,000 个样本。采样率是多少？如果每个样本用 12 bits，理论上可区分多少个量化值？
3. 对同一段未压缩单声道录音，采样率翻倍、bit depth 不变，文件数据量如何变化？解释原因。
4. `640×480`、16-bit 色深的图像有多少 pixels？每像素最多能表示多少种颜色？
5. 图像宽高均减半且色深不变，其像素数据量变为原来的多少？

### Answers:


1. 基本 ASCII 的字符数量有限，主要涵盖基础英语字符；Unicode 可给更多语言字符分配编号。
2. `20,000 Hz = 20 kHz`；`2¹² = 4096` 个量化值。
3. 约两倍；同样的录音时长内，每秒记录的样本数变成两倍。
4. `640×480 = 307,200 pixels`；`2¹⁶ = 65,536` 种编码。
5. `1/2 × 1/2 = 1/4`。

### 📝 Lecture 04 · Storage Units & File Size Calculations

### 📌 学习目标

1. 区分 bit、byte、KiB、MiB 与十进制存储单位。
2. 计算未压缩 bitmap image 与 PCM sound 的理论数据量。
3. 说明这些公式忽略哪些实际文件开销。

### 1. 先统一单位

`1 byte (B) = 8 bits (b)`；小写 `b` 与大写 `B` 意义不同。`1 nibble = 4 bits`。

| 二进制单位 | 字节数 | 十进制单位 | 字节数 |
|---|---:|---|---:|
| 1 KiB | 1,024 B | 1 KB | 1,000 B |
| 1 MiB | 1,048,576 B | 1 MB | 1,000,000 B |
| 1 GiB | 1,073,741,824 B | 1 GB | 1,000,000,000 B |

教材这一章侧重 IEC 的 **KiB / MiB / GiB**。计算时始终留意题目指定单位；`MiB` 与 `MB` 不应混用。

### 2. 未压缩位图图像

```text
pixel data (bits) = width (pixels) × height (pixels) × colour depth (bits/pixel)
file data (bytes) = pixel data (bits) ÷ 8
```

**示例：** `800×600`、24-bit 色深：`800×600×24 = 11,520,000 bits`，即 `1,440,000 B`，约 `1.37 MiB`（除以 1,048,576）。

实际图像文件可能还包含元数据、行填充或经过压缩；题目若仅提供分辨率与色深，求的是**未压缩像素数据量**。

### 3. 未压缩音频

```text
sound data (bits) = sampling rate (samples/s) × bit depth (bits/sample)
                    × duration (s) × channel count
```

单声道 `channel count = 1`；双声道 stereo 为 `2`。

**示例：** 48 kHz、16-bit、10 秒、stereo：

```text
48,000 × 16 × 10 × 2 = 15,360,000 bits
÷ 8 = 1,920,000 B
÷ 1,048,576 ≈ 1.83 MiB
```

`kHz` 要先转换成 Hz（`48 kHz = 48,000 Hz`）；分钟要换成秒。这里同样未计文件头和压缩。

### 4. 常见丢分点

| 错误 | 纠正 |
|---|---|
| 把 bit 当 byte | 除以 8，写清单位 |
| 直接把分钟代入 | 先乘 60 得到秒 |
| 双声道漏乘 2 | 明确 channel count |
| 将 KB 与 KiB 混用 | 按题意选 1000 或 1024 |
| 将编码后文件大小套未压缩公式 | 公式只给原始数据量 |

### Questions:

1. `1,638,400 bits` 等于多少 bytes、多少 KiB？
2. 一张 `1024×512`、8-bit 色深的未压缩位图，像素数据量是多少 KiB？写步骤。（3 marks）
3. 一段 2 分钟的 mono 音频，采样率 8 kHz，bit depth 8 bits，未压缩音频数据量是多少 bytes 和 KiB？（4 marks）
4. 上题若改为 stereo、其他不变，答案如何变化？
5. 图像分辨率不变、色深由 8 bit 升为 24 bit，像素数据量变为多少倍？

### Answer:


1. `1,638,400÷8=204,800 B`；`204,800÷1024=200 KiB`。
2. `1024×512×8÷8=524,288 B=512 KiB`。
3. `2 min=120 s`；`8000×8×120×1÷8=960,000 B=937.5 KiB`。
4. 翻倍，`1,920,000 B=1,875 KiB`。
5. `24÷8=3` 倍。

### 📝 Lecture 05 · Compression & Chapter Review

### 📌 学习目标

1. 解释压缩文件对存储和传输的作用。
2. 比较 lossy 与 lossless，并为不同用途选择合适方式。
3. 手工完成简化的 run-length encoding（RLE）及解码。

### 1. 为什么压缩？

数据量减少，通常意味着占用较少的存储空间，并减少上传、下载或流式传输所需的数据量。它能节省传输时间或带宽；具体速度还取决于网络条件及压缩、解压所花时间。

### 2. 两种方式

| | Lossless（无损） | Lossy（有损） |
|---|---|---|
| 解压后能否恢复原始数据 | 能逐 bit 恢复 | 不能完全恢复 |
| 典型用途 | 程序、文档、需要精确保留的数据 | 照片、音乐、视频等允许一定感知损失的内容 |
| 本章例子 | RLE | JPEG、MP3；教材也提及 MP4 媒体文件 |

**选择原则：** 软件程序少了一个 bit 都可能失效，应选择无损；要把照片发给朋友且可接受细节损失，可以考虑有损。文件格式名称本身不保证所有具体文件都采用相同参数或画质。

有损压缩会丢弃部分信息。例如图像可削减某些人眼较难察觉的细节；音频可减少不容易听到的成分。被丢弃的信息在解压后无法精确恢复。

### 3. Run-length encoding（RLE，游程编码）

RLE 将**连续重复**的值写为“重复次数 + 值”。本节使用教学用简化格式 `(count, symbol)`：

```text
原始: AAAAABBBCCAAAA
编码: (5,A)(3,B)(2,C)(4,A)
解码: 连续写 5 个 A、3 个 B、2 个 C、4 个 A
```

首尾两段 `A` **不相邻**，不能合并。若原始内容是 `ABCDEFG`，简化 RLE 编码成七组 `(1,…)` 可能更长；实际编码需要规定如何存储 count、symbol 和特殊标记，不能仅凭组数就断言节省了多少 bytes。

**场景讨论：** 单色图标有大量连续相同像素，RLE 往往更有效；颜色频繁变化的图片中连续重复段短，收益可能很小。

### 4. 全章知识链

1. 进制：数值可用 binary / denary / hex 表示，hex 的每位对应 4 bits。
2. 运算：固定字长可能 overflow，逻辑移位丢弃移出的 bit，补码解释有符号整数。
3. 编码：字符映射为编号；声音按时间采样；位图由像素构成。
4. 体积：图像 = 像素数 × 色深；声音 = 采样率 × 位深 × 时长 × 声道数。
5. 压缩：减小数据量；无损可恢复原件，有损无法精确恢复。

### Questions:

1. 把 `10101111₂` 转成 hex 和 denary。（2 marks）
2. 一幅 `200×100`、16-bit 的未压缩位图有多少 bytes？（2 marks）
3. 如果图像宽高均翻倍而色深不变，说明新像素数据量为何是原来的四倍。（2 marks）
4. 把 `RRRRRRGGBBBBB` 写为本课的简化 RLE 格式。（2 marks）
5. 一个学生要压缩程序安装包和旅行照片，请分别选择有损/无损，并解释理由。（4 marks）
6. 16 kHz、8-bit、5 秒的 mono 未压缩音频需要多少 KiB？（3 marks）

### Answer:


1. `1010 1111₂ = AF₁₆`；`128+32+8+4+2+1 = 175₁₀`。
2. `200×100×16÷8=40,000 B`。
3. 原像素数为 `w×h`，变成 `(2w)×(2h)=4wh`；每个像素 bit 数不变，因此数据量变成四倍。
4. `(6,R)(2,G)(5,B)`。
5. 安装包选 lossless，必须精确恢复数据；照片可以选 lossy 以减小文件，接受可能损失细节。如果必须保留原始照片，也应使用 lossless。
6. `16,000×8×5÷8=80,000 B`；`80,000÷1024=78.125 KiB`。

- `1 hex digit = ? bits`（4）
- `Why can lossy compression not reproduce the original file?`（部分原始信息已被永久丢弃）
- `What changes file size if image resolution stays the same?`（例如增加 colour depth）
