## ACSL Senior：ACSL Tiles 编程题解析

本章知识点：规则模拟、状态设计、循环优先顺序、动态数组删除、取模轮转、字符串解析、边界条件与调试。

### 1. 📌 题意：把牌接到四行的末尾

桌面上有四行，每行最初只有一个数字。输入 `5923` 表示四行起点分别是 5、9、2、3。

每张牌有两个数字，例如 `56` 的两端为 5 和 6。牌可以翻转，因此 `56` 与 `65` 的匹配能力相同。

若一行末尾为 5，就能接上 `56`，接完后末尾变成 6。

你有一列有顺序的手牌 hand，以及一列有顺序的摸牌堆 draw。按照题目的固定顺序出牌，最终计算剩余手牌上所有数字的和。

> 本题的行动已经由规则决定，不需要寻找最优出牌策略。重点是准确模拟。

### 2. 📌 六条核心规则

#### 2.1 先选牌，再选行

从手牌第一张开始，对当前这张牌检查允许的行。若能放，立即放置；若不能放，再检查下一张手牌。

```text
for 每张手牌（从前到后）:
    for 当前允许的行（按规定顺序）:
        如果能放:
            放置并结束这次出牌
```

不能写成“先选一行，再找能放到该行的牌”。这样会改变出牌优先级。

#### 2.2 行的检查顺序会轮转

第一次从第 1 行开始。普通情况下，下一次从上一次出牌行的下一行开始，循环检查四行。

| 上次出牌位置 | 下一次检查顺序 |
|---|---|
| 第 1 行 | 2 → 3 → 4 → 1 |
| 第 2 行 | 3 → 4 → 1 → 2 |
| 第 3 行 | 4 → 1 → 2 → 3 |
| 第 4 行 | 1 → 2 → 3 → 4 |

注意：上次出牌行仍可能被选中，只是在普通轮转中排最后。

#### 2.3 每次成功出牌后，重新从手牌开头查找

牌局状态改变后，之前不能出的牌可能已经可以出。不能继续沿用上次删除位置后面的下标。

题面中 `34` 先被跳过，等 `32` 放下后，`34` 又可以被选中。

#### 2.4 双牌会锁定一行

两端相同的牌，例如 `99`、`22`、`00`，叫 double。

如果刚放下双牌，下一张成功放下的牌必须继续放在同一行。即使其他行能接牌，也不能考虑。

- 找不到能放到锁定行的手牌：只能继续摸牌。
- 在锁定行放下非双牌：解除锁定。
- 在锁定行又放下双牌：继续锁定。
- 手里已经没有牌：立即结束，不必额外摸牌来解除锁定。

#### 2.5 手牌无牌可出，才摸牌

必须完整检查当前所有手牌。若均不能出，就从摸牌堆前端取一张，追加到手牌末尾，再检查。

若新牌仍不能出，它保留在手牌末尾，继续摸下一张。

每次摸牌后重新扫描所有手牌，是一种简单且正确的实现：摸牌不改变行尾、轮转起点或锁定行，原来不能出的旧牌仍不能出。

#### 2.6 两种结束条件

1. 手牌已经为空。
2. 所有手牌都不能出，且摸牌堆已经耗尽。

**摸牌堆为空不代表立刻结束**，剩余手牌可能还可以继续出。

### 3. 📌 数据如何表示？

| 状态 | 建议变量 | 含义 |
|---|---|---|
| 四行末尾 | `array<int, 4> ends` | 只记录每行当前末尾的数字 |
| 当前手牌 | `vector<int> hand` | 保留顺序及重复牌 |
| 摸牌堆 | `vector<int> draw` | 保存原始顺序 |
| 下张待摸牌 | `int drawPos` | 从 0 开始递增 |
| 普通轮转起点 | `int start` | 下一次首先尝试的行，0-based |
| 锁定行 | `int locked` | -1 为未锁定；0–3 为锁定行 |

**为什么只需要存每行末尾？**

后续牌能否放置只依赖行尾，最终答案也只依赖手牌。整行历史可以省略。

**为什么不能用 set 保存手牌？**

它会排序、去重，破坏原来的优先顺序，也会丢失重复牌。

#### 前导 0 的处理

行起点整数 `405` 必须解释为 `0,4,0,5`；`4` 是 `0,0,0,4`；`0` 是 `0,0,0,0`。

```cpp
for (int i = 3; i >= 0; i--) {
    ends[i] = originalRows % 10;
    originalRows /= 10;
}
```

牌的两个端点可以直接拆分：

```cpp
int a = tile / 10;
int b = tile % 10;
```

例如整数 `6` 表示 `06`，整数 `0` 表示双牌 `00`。摸牌堆输入 `"0"` 表示一张 `00`，不是空牌堆。

### 4. 📌 判断一张牌能放在哪行

若行尾是 `ends[r]`，牌的两端为 a、b，则匹配条件为：

```cpp
ends[r] == a || ends[r] == b
```

成功后，新行尾为另一个端点：

```cpp
ends[r] = (ends[r] == a ? b : a);
```

无需实际交换 a、b，也无需存储牌朝向。

普通情况下，依次检查：

```cpp
int r = (start + offset) % 4; // offset = 0, 1, 2, 3
```

锁定情况下，只检查 `locked`。

### 6. 📌 主循环设计

```text
只要手牌不为空：
    从手牌第一张开始，寻找第一张能出的牌及其合法行

    如果找到：
        更新行尾
        更新普通轮转起点
        根据是否为双牌更新锁定状态
        删除该张手牌
        开始下一次循环，重新从手牌第一张检查
    否则：
        如果还能摸牌：
            摸一张，加入手牌末尾
        否则：
            结束

计算剩余手牌的各位数字和
```

每次循环或者成功出一张牌，或者消耗摸牌堆一张牌，或者直接终止，因此不会无限循环。

### 7. C++17 参考代码

保留题面要求的函数接口 `findHandSum`。下方 main 只是本地运行驱动，读取一组数据的三行；样例中显示的 `1.`、`2.` 是题目编号，不属于输入。

```c++
while (!hand.empty()) {
    // 1. 从头找第一张能出的牌。

    // 2. 找到：更新行尾、轮转起点、锁定状态，删除牌。
    //    然后重新从手牌开头检查。

    // 3. 找不到：摸一张牌。
    //    没牌可摸则结束。
}
```

```cpp
#include <array>
#include <iostream>
#include <sstream>
#include <string>
#include <vector>
using namespace std;

// 将空格分隔的数字字符串转换为数组。
// 例如："56 27 3" → {56, 27, 3}
// 整数 3 表示牌 03，整数 0 表示牌 00。
vector<int> parseTiles(const string& text) {
    istringstream input(text); // 从字符串 text 中读取数据
    vector<int> tiles;
    int tile;

    while (input >> tile) {
        tiles.push_back(tile);
    }

    return tiles;
}

// 为当前这张牌寻找第一个合法的行。
// ends：四行当前末尾的数字
// tile：当前要尝试的牌
// start：未锁定时，从这个行下标开始轮转检查
// locked：-1 表示未锁定，否则只能检查该行
// 返回值：可以放入的行下标；无处可放则返回 -1
int findRow(const array<int, 4>& ends,
            int tile, int start, int locked) {
    int a = tile / 10; // 牌的十位，即一个端点
    int b = tile % 10; // 牌的个位，即另一个端点

    // 双牌锁行期间，只允许接到锁定行。
    if (locked != -1) {
        if (ends[locked] == a || ends[locked] == b) {
            return locked;
        }
        return -1;
    }

    // 未锁定时，从 start 开始，依次循环检查四行。
    // 例如 start = 2，检查下标顺序为 2、3、0、1。
    for (int offset = 0; offset < 4; offset++) {
        int r = (start + offset) % 4;

        // 牌可以翻转，任意一端匹配行末尾即可。
        if (ends[r] == a || ends[r] == b) {
            return r;
        }
    }

    return -1;
}

// 按照游戏规则模拟，返回最终剩余手牌的各位数字之和。
int findHandSum(int originalRows,
                string handTiles,
                string drawPile) {
    array<int, 4> ends{};

    // 从右向左拆出四行的起点，自动保留前导 0 的含义。
    // 例如 405 → {0, 4, 0, 5}。
    for (int i = 3; i >= 0; i--) {
        ends[i] = originalRows % 10;
        originalRows /= 10;
    }

    vector<int> hand = parseTiles(handTiles);
    vector<int> draw = parseTiles(drawPile);

    int drawPos = 0;  // 下一张待摸牌的下标
    int start = 0;    // 第一次从第 1 行（下标 0）开始检查
    int locked = -1;  // 初始没有锁定行

    // 手牌为空时立即结束，即使摸牌堆还有牌。
    while (!hand.empty()) {
        bool played = false; // 本轮是否成功出了一张牌

        // 优先按手牌顺序选牌，再为当前牌寻找合法行。
        for (int i = 0; i < static_cast<int>(hand.size()); i++) {
            int tile = hand[i];
            int r = findRow(ends, tile, start, locked);

            // 当前牌无处可放，继续检查下一张手牌。
            if (r == -1) {
                continue;
            }

            int a = tile / 10;
            int b = tile % 10;

            // 匹配的一端接到行尾，另一端成为新的行尾。
            // 例如行尾为 3，牌是 73，新行尾就是 7。
            ends[r] = (ends[r] == a ? b : a);

            // 下一次普通轮转从当前行的下一行开始。
            start = (r + 1) % 4;

            // 双牌：锁定当前行。
            // 非双牌：解除锁定，恢复普通轮转。
            locked = (a == b ? r : -1);

            // 删除已经放下的牌，其余手牌的相对顺序不变。
            hand.erase(hand.begin() + i);

            played = true;

            // 一次只出一张牌。
            // 删除后立即结束 for，避免继续使用旧的下标位置。
            break;
        }

        // 成功出牌后进入下一轮 while。
        // 下一轮 for 从 i = 0 开始，重新检查之前跳过的牌。
        if (played) {
            continue;
        }

        // 运行到这里，说明整副手牌都没有可出的牌。
        if (drawPos < static_cast<int>(draw.size())) {
            // 按顺序摸一张牌，追加到手牌末尾。
            hand.push_back(draw[drawPos]);
            drawPos++;

            // 随后进入下一轮 while，再次尝试出牌。
        } else {
            // 手牌无法出，摸牌堆也已耗尽，游戏结束。
            break;
        }
    }

    // 统计剩余牌两个端点的数字和，而不是牌面整数之和。
    // 例如剩余 11、36、50，答案为 2 + 9 + 5 = 16。
    int answer = 0;
    for (int tile : hand) {
        answer += tile / 10 + tile % 10;
    }

    return answer;
}

// 本地测试入口：读取一组数据，共三行。
// 若平台要求只提交 findHandSum，则不提交 main。
int main() {
    int originalRows;

    if (!(cin >> originalRows)) {
        return 0;
    }

    string line, handTiles, drawPile;

    // cin >> originalRows 后，换行仍留在输入流中。
    // 先读取本行剩余内容，避免下一次 getline 读到空字符串。
    getline(cin, line);

    getline(cin, handTiles); // 第二行：初始手牌
    getline(cin, drawPile);  // 第三行：摸牌堆

    cout << findHandSum(originalRows, handTiles, drawPile) << '\n';

    return 0;
}
```

代码讨论：删除元素后立即 break，不会用已经失效的引用或旧位置继续遍历。`start` 在锁定时也更新，但只有解锁后才参与选行。

### 8. 正确性与复杂度

**状态正确**：初始 ends、手牌和摸牌堆均按输入建立；start 指向第 1 行，locked 为未锁定。

**每次行动正确**：外层遍历保证先尝试最早的手牌；findRow 保证按行轮转或锁行规则寻找位置；找到后只更新受影响的行尾、轮转起点、锁定状态和手牌。未找到时，才摸取下一张牌或结束。

因此每次循环前保存的状态都与真实牌局一致，最后对正确的剩余手牌求数字和即可。

设初始手牌数为 H，摸牌堆牌数为 D，总牌数为 N = H + D。

- 成功出牌最多 N 次，摸牌最多 D 次。
- 每次扫描手牌和删除一个 vector 元素，均最多 O(N)；每张牌只查最多四行。
- 总时间 **O(N²)**，空间 **O(N)**。本题用直接模拟即可；试课不必优先追求更复杂的数据结构优化。
